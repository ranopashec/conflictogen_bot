# Conflictogen — конфликты для SSL

Telegram-бот: https://t.me/conflictogen_bot

Генерирует законченные конфликтные ситуации на русском языке по правилам школы SSL. Пользователь подключает собственный API-ключ Gemini или Groq. В ответе только текст ситуации; роли и редакторские проверки остаются внутри генератора.

## Возможности

- Генерация с учётом 41 школьного примера, выбранной темы и формата.
- Проверка структуры, связности ролей, завершённости текста, сходства с готовыми кейсами и отдельная модельная редактура.
- Личный банк: `/add`, `/bank`, сохранение генераций и копий из общего банка.
- Общий банк: `/public`. Публикация предложений через администраторскую очередь `/review`.
- Личные записи видит только автор. Администраторы получают только явно предложенные тексты.
- Ключи пользователей шифруются в SQLite. `/forget` удаляет ключ; `/delete_me` удаляет личные данные. Уже опубликованные копии остаются в общем банке, о чём бот предупреждает перед отправкой предложения.
- Список моделей запрашивается у провайдера. При 404 генератор один раз пробует актуальную альтернативу.

## Локальный запуск

Нужен Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```sh
git clone https://github.com/ranopashec/conflictogen_bot.git
cd conflictogen_bot
uv sync --frozen
uv run python setup_local.py
git config core.hooksPath .githooks
```

В локальном `.env` укажи `TELEGRAM_BOT_TOKEN` из BotFather и числовые Telegram ID администраторов в `ADMIN_IDS`. `setup_local.py` создаёт ключ шифрования автоматически и не перезаписывает существующий файл. `ENCRYPTION_KEY` нужно сохранять вместе с базой при переносах.

```sh
uv run python -m conflict_bot.bot
```

Затем в Telegram: `/start` → `/connect` → выбрать провайдера → отправить его API-ключ → «Новый конфликт». Личный и общий банки работают без ключа LLM. Тарифы и квоты зависят от аккаунта пользователя у провайдера. Одна генерация выполняет до четырёх запросов к модели, плюс один при замене недоступной модели.

Два экземпляра с одним Telegram-токеном запускать одновременно нельзя.

## Сервер и автоматическое обновление

Полная инструкция для администратора: [DEPLOY.md](DEPLOY.md).

После первоначальной установки сервер раз в минуту проверяет `main`, собирает новую версию с обязательными тестами и обновляет только контейнер этого проекта. Секреты хранятся в `/etc/conflictogen-bot.env`, база — в отдельном Docker volume. Новые версии не требуют повторного ввода пользовательских ключей. GitHub не получает токен Telegram, ключ шифрования или доступ к серверу.

В репозитории также есть GitHub Actions: тесты, проверка секретов и Docker-сборка при пуше в `main` и при pull request. Автоматический серверный деплой проверяет тесты повторно независимо от Actions.

## Секреты и проверки

```sh
uv run pytest -q
python3 scripts/check_secrets.py
```

Сканер проверяет индекс Git: запрещённые env-файлы, базы, распознаваемые ключи и точные значения из локального `.env`. Он не выводит найденные секреты. Pre-push hook запускает эту проверку, если настроен `core.hooksPath`. Файлы `.env*`, ключи, базы и логи исключены через `.gitignore` и `.dockerignore`; `.env.example` содержит только пустые значения.

Нельзя добавлять секреты принудительно через `git add -f`. Автоматическая проверка — дополнительная защита; она не распознаёт все возможные форматы секретов.

API-ключ проходит через Telegram и процесс бота. Исходное сообщение бот пытается удалить. Администратор с доступом к базе и `ENCRYPTION_KEY` технически может расшифровать сохранённые ключи. HTTP-токены, входящие сообщения и ответы провайдеров не пишутся в журналы.

Правила составления кейсов: [CRITERIA.md](CRITERIA.md). Автоматическая редактура не гарантирует качество тренера и отсутствие всех смысловых повторов.
